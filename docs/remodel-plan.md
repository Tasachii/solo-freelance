## กรอบ: Solo คือแพลตฟอร์ม ติวเตอร์คือ vertical แรก

เป้าหมายจริงคือ **แอดมินหลังบ้านให้ฟรีแลนซ์ทุกอาชีพที่ทำงานคนเดียว** — ช่างเล็บ ช่างตัดผม แม่บ้าน ครูดนตรี เทรนเนอร์ ช่างภาพ … ติวเตอร์เป็นแค่คนแรกที่เราลงไปคุยแล้วเจ็บจริง

ผลต่อแผนนี้: ทุก commit ต้องผ่านคำถามเดียว — *"ถ้าพรุ่งนี้เพิ่ม `professions/nail.ts` จะต้องแตะไฟล์นี้ไหม"* ถ้าใช่ แปลว่าวางผิดชั้น · C1 (ตาราง/เลื่อน) C2 (สรุปพัฒนาการ) C5 (แพ็ก) ออกแบบเป็น "หน่วยงาน / โน้ตหลังงาน / แพ็กบริการ" ใน `core/` แล้วให้ `professions/tutor.ts` ตั้งชื่อว่า คาบ / โน้ตหลังคาบ / คอร์ส — ช่างเล็บได้ "คิว / โน้ตหลังคิว / คอร์ส" ฟรีโดยไม่ต้องเขียนอะไรใหม่

- **เทสมี 42 unit + 18 e2e** ไม่ใช่ 22 — ทั้งหมดต้องผ่านตลอด
- **แท็บมี 4 แล้ว** (วันนี้ · รายชื่อ · บิล · แอดมิน) — B2 ข้อนี้จบไปแล้ว
- **rename ค้างครึ่งทาง**: commit `63d4d20` เปลี่ยน package/base เป็น `solo` แล้วแต่**ยังไม่ push** · GitHub ยังชื่อ `solo-tutor` · ถ้า push ตอนนี้เว็บพังทันที (base `/solo/` บน repo ชื่อเดิม) — ต้อง rename GitHub ก่อน push

## ต้องให้คุณตัดสินใจ 4 ข้อ

1. **ลบหน้า `/pitch` ทิ้งเลย** (รวมตาราง Engine) — ตรงกับ "ไม่ต้องมี pitching mode" แต่ขัดกติกาข้อ 8 "ห้ามลบฟีเจอร์เดิม" · ผมแนะนำ**ลบ** เพราะมันคือของ pitch ทั้งหน้า
2. **ปัดขวา = ส่งข้อความหาผู้ปกครอง** — ผมขอ**ไม่ทำ** ปัดพลาดบนมือถือแล้วข้อความออกไปหาผู้ปกครองจริง ขัดหลักการข้อ 3 · เสนอ: ปัดซ้าย = ข้าม (กู้คืนได้) · **ส่ง = แตะปุ่มเสมอ** · card stack ยังทำ
3. **palette ตามสไลด์** ข้างบน — หรืออยากคงโทน teal เดิม
4. **rename ทำให้ลิงก์เก่า `…/solo-tutor/` ตายถาวร** (GitHub Pages ไม่ redirect) — ยืนยันว่ารับได้ แล้วผมจะรัน `gh repo rename` ให้เลย

## ความเสี่ยงที่รู้ล่วงหน้า

- **Migration v3→v4** — เทสด้วย snapshot จริงจาก localStorage ของเครื่องนี้ ไม่ใช่ fixture ที่แต่งเอง
- **C1 ห้ามกระทบเงิน** — โครงสร้างเดิมช่วยอยู่แล้ว (บิลคิดจาก completions ไม่ใช่ units) แต่ต้องมีเทสคุมไม่ให้ใครเผลอผูกทีหลัง
- **Repo async แต่ UI ต้อง sync วันนี้** — `status: loading` จะโผล่ 1 เฟรม ถ้าไม่จัดการดี ๆ จอจะกระพริบทุกครั้งที่เปิด
