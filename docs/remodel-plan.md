| คำแนะนำ | ผล |
|---|---|

| เลือกฟีเจอร์หลัก เช่น "ติดตามการเรียน" | เฟส 2 ทั้งเฟสคืออันนี้ |

## เรื่องใหญ่ที่เพิ่งเจอ — วงจรของแอปยังไม่จบ

ปุ่ม **"ส่ง"** ทุกวันนี้ทำแค่เปลี่ยนสถานะใน state เป็น `sent` แล้วเพิ่มฟองแชทจำลอง
**ไม่มีการคัดลอก ไม่มีการเปิด LINE ไม่มีอะไรออกไปข้างนอกเลย**

สำหรับเดโมไม่เป็นไร แต่ถ้าให้ครูจริงใช้ นี่คือจุดที่ทำให้แอปไร้ประโยชน์ — ครูยังต้องพิมพ์เองใน LINE อยู่ดี ซึ่งคือปัญหาเดิมที่ 42/50 คนทำอยู่

## เชื่อม LINE — ทางที่ทำได้จริงวันนี้

| ทาง | ต้องมีอะไร | เหมาะไหม |
|---|---|---|
| **LINE share link** `line.me/R/share?text=…` | ไม่ต้องมีอะไรเลย · static ล้วน | ✅ **เลือกอันนี้** |
| Messaging API (บอทส่งเอง) | server + webhook + ผู้ปกครองต้องแอดบอทเป็นเพื่อน | ❌ |

ที่สำคัญกว่าเรื่องถูก/แพง: **share link ถูกต้องกว่าในเชิงโปรดักต์**
- ข้อความออกจากบัญชี LINE ของครูเอง = ตรงหลักการข้อ 5 (เสียงของผู้ให้บริการ) เป๊ะ
- ครูเลือกแชทเองแล้วกดส่งเอง = ตรงหลักการข้อ 3
- สัมภาษณ์บอกว่า *"ผู้ปกครองเข้าถึงแอปหรือลิงก์ได้ยาก"* — บอทยิ่งแย่ เพราะต้องให้เขาแอดเพื่อนก่อน ส่วน share link ไปโผล่ในแชทเดิมที่คุยกันอยู่แล้ว

บนเดสก์ท็อปที่ไม่มี LINE ให้ fallback เป็นคัดลอกข้อความ + บอกด้วย toast

## เฟส 1 · ทำให้วงจรจบจริง

| งาน | รายละเอียด |
|---|---|
| `feat(line)` **ส่งเข้า LINE ได้จริง** | ปุ่มส่ง → เปิด LINE พร้อมข้อความ · เดสก์ท็อปคัดลอกให้ · สถานะเป็น `sent` **ต่อเมื่อ**ครูยืนยันว่าส่งแล้ว ไม่ใช่แค่กดเปิด |
| `feat(real)` **โหมดใช้จริง** | สลับจากข้อมูลเดโมเป็นข้อมูลตัวเอง · ป้าย "เดโม" หายเมื่ออยู่โหมดจริง · onboarding ใส่รายชื่อจริง |
| `feat(backup)` **กันข้อมูลหาย** | สำรอง/กู้คืนเป็นไฟล์ JSON · เตือนเมื่อไม่ได้สำรองนาน — `localStorage` อยู่เครื่องเดียว ล้างแคชแล้วหายหมด ครูจริงรับความเสี่ยงนี้ไม่ได้ |

## เฟส 2 · ติดตามการเรียนให้สมบูรณ์ (ที่เมนเทอร์ชี้)

ทั้งสามข้อคือฟีเจอร์เดียวกัน — *บันทึกว่าเกิดอะไรขึ้น แล้วให้ผู้ปกครองเห็น*

| งาน | ทำไม |
|---|---|
| `feat(schedule)` **เลื่อน/ยกเลิกคาบ** | 3/8 คนขอเอง · ถ้าไม่มี บันทึกการเรียนจะผิดทันทีที่ชีวิตจริงเกิดขึ้น · เก็บเป็น event ใน ledger · **ห้ามกระทบยอดบิลจนกว่าจะเช็คชื่อจริง** |
| `feat(progress)` **โน้ตต่อคาบ + สรุปเดือน** | โหวตอันดับ 2 (12/50) · โน้ต 1 บรรทัดหลังเช็คชื่อ → สิ้นเดือนร่างสรุปเข้ากล่องรอส่ง |
| `feat(client)` **ผู้ปกครองเห็นจำนวนครั้งเอง** | 26/50 ถูกถาม "เรียนไปกี่ครั้งแล้ว" เดือนที่แล้ว · ตอบให้โดยครูไม่ต้องตอบ |

## ตัดออกจากแผนเดิม (เก็บไว้ทำทีหลัง)

| ตัด | เหตุผล |
|---|---|
| `src/data/` Repo abstraction · migration v3→v4 · uuid · `providerId` | เป็นสถาปัตยกรรมเผื่อหลังบ้านที่ยังไม่มี · แทนด้วยสำรองไฟล์ JSON ซึ่งแก้ปัญหาจริงข้อเดียวกัน (ข้อมูลหาย) ด้วยแรง 1/10 |
| redesign ทุกหน้า (7 หน้า) | ขัดเฉพาะ 3 จอในวงจรหลัก |
| C4 banner สรุปวัน · C6 กราฟรายรับ · C7 dueDays รายคน | ไม่มีใครในผลสำรวจขอ |

**ยังยึดเหมือนเดิม:** ทุกอย่างสร้างใน `core/` แบบไม่รู้จักอาชีพ — โน้ตหลังคาบ/เลื่อนคาบ ต้องเป็น "โน้ตหลังงาน / เลื่อนหน่วยงาน" ที่ `professions/nail.ts` เอาไปใช้ได้ฟรีวันหน้า

## ต้องให้คุณตัดสินใจ 2 ข้อ

1. **โหมดใช้จริง = ข้อมูลอยู่บนเครื่องครูเท่านั้น** ล้างแคช/เปลี่ยนเครื่อง = หาย · ผมกันด้วยไฟล์สำรอง แต่ต้องบอกครูตรง ๆ ตอนเริ่มใช้ · รับได้ไหม หรืออยากให้หา backend ฟรี (Supabase) ก่อนปล่อยให้ใครใช้
2. **ครู 1–2 คนที่จะให้ลอง มีตัวจริงหรือยัง** — ถ้ามี บอกจำนวนนักเรียนกับวิธีเก็บเงินของเขา ผมจะได้ทำ onboarding ให้พอดีกับเคสเขาจริง ๆ ไม่ใช่เดา
